11. IMPORTANT RULES

---

* Public subnet = subnet whose route table has 0.0.0.0/0 → Internet Gateway.
* Private App subnet = uses NAT Gateway for outbound Internet.
* Private DB subnet = no Internet route.
* NAT Gateway must be placed in a public subnet.
* Route tables are associated with subnets.
* Do not expose private application/database subnets directly to the Internet.
* Do not add an Internet Gateway route to private DB subnets.

# AWS Security Groups — Quick Note

Security Groups act as **virtual firewalls** for AWS resources.

### 1. ALB Security Group — `employee-alb-sg`

* Protects the Load Balancer
* **Inbound:** TCP `80` from Internet
* **Inbound:** TCP `443` from Internet (for future HTTPS)
* **Outbound:** Allow all

```text
Internet → ALB :80/:443
```

### 2. EC2 Security Group — `employee-ec2-sg`

* Protects the EC2 application server
* **Inbound:** TCP `80` from `employee-alb-sg`
* No public SSH because we use SSM
* Backend ports `3000, 5000, 8000, 8080` are not exposed
* **Outbound:** Allow all

```text
ALB → EC2 :80
```

### 3. RDS Security Group — `employee-rds-sg`

* Protects RDS MySQL
* **Inbound:** TCP `3306` from `employee-ec2-sg`
* No public access to MySQL
* **Outbound:** Allow all

```text
EC2 → RDS :3306
```

### Final Flow

```text
Internet
   ↓ :80/:443
ALB
   ↓ :80
EC2 / NGINX
   ↓ :3306
RDS MySQL
```

**Important:** The port in an SG rule is the **destination port on the resource receiving the connection**.
